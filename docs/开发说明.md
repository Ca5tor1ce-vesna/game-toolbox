# 游戏实用工具箱 · 开发说明

> 写给作者和想改代码的人。普通使用请看仓库首页的 README。部分界面描述（如顶部快捷区）是 0.17.0 改版前的，以 `修改记录.md` 为准。

一个可以**不断往里加功能**的游戏工具箱。一套代码，同时是网页版和桌面窗口版。

现在里面有：

* **崩坏：星穹铁道**
  * 🎯 **配速查询** —— 选角色 →（只列同命途的）光锥 → 星魂/**遗器 4 件套与两个位面饰品**，算出实际速度；再给出**混沌回忆、异相仲裁、虚构叙事、末日幻影**各 T 数 × 各动数需要的速度。
    * 角色按**推出顺序**排列（新角色在最上面），角色/光锥/遗器下拉都带**官方图标**，选中角色时左侧显示**官方立绘**；
    * **角色初始速度已包含行迹（属性加成）里的速度**，例如镜流 96 + 行迹 2/3/4 = 105；界面上会把「基础 + 行迹」拆开显示，公式里也写明；
    * **每条效果都标了触发方式**——「加速」不都是开局就生效的：`常驻`（开局就有，默认勾上）、`进战`（进入战斗触发，开局即生效）、`开大`（要先开大，**开大次数为 0 时不计入**）、`条件`（需要满足特定条件，绝不自动计入）。遗器套装里那种「施放终结技后我方全体速度 +12%」也按这个规则计入——**以前这类会被静默丢掉，把速度算低**；
    * **顶部有「⚡ 配装与加成」快捷区**：遗器 4 件套 / 位面饰品 / 速度鞋 / 副词条 / 开大次数 / 轴底开大 在角色卡片里就能改，和下面的卡片**双向同步**，不用来回滚；
    * 数据里会**过滤掉不算自己战斗速度的干扰项**（「目标的速度降低 20%」是给敌人减速、「移动速度提高 50%」是大地图跑图），避免这两类混进配速；
    * **遗器池是全量的**：34 个 4 件套遗器 + **1 个位面饰品栏位**（28 个可选）都能选；**没有速度效果的套装选了就选了，计算时自动不计入**（只影响配速的部分才参与运算）；
    * **「轴底开大」勾选**：勾上就把最后一次开大触发的拉条扣掉（收尾那次开大帮不到前面几动）——风套、舞！舞！舞！、光锥拉条都会少算一次，进战拉条（翁瓦克）不受影响；
    * 角色卡片里有一块**配速小结**：左边选了什么遗器、套装的配速贡献，以及当前目标的「需要速度 / 当前速度 / 还差多少 / 该行动值能打几动」；
    * 角色天赋/星魂/技能/行迹/光锥/遗器的速度与拉条效果，全部从官方文案里自动抽取后列出来供勾选；**风套（开大拉条 25%）、翁瓦克（进战拉条 40%）、舞！舞！舞！（按叠影 16%~24%）选中即自动计入**，带条件的不自动算而是单独列出；
    * 目标可以按 T 数选，也可以**直接指定行动值节点**；
    * 速度不够时给出**补足建议表**：堆多少副词条、换速度鞋、上翁瓦克/风套各能到多少、够不够；
    * **🧠 自动推荐配装**：在你能用的光锥/遗器范围内穷举（约 2000+ 套），直接列出「达成当前目标最省」的几套，一键套用。这是自动算的最优解，**不是社区主流配装表**（米游社详情接口与常见 wiki 都拿不到那个数据，见下）；
    * 配装可以「存为我的配装」，存在 `userdata/` 里，升级代码不会丢。

  **各模式行动值口径**（容易踩坑，单独说明）：行动值 = 10000 / 速度。混沌回忆、虚构叙事、末日幻影是**首轮 150 AV、其后每轮 100 AV**；**异相仲裁（骑士关与王棋关同结构）是首轮 300 AV、其后每轮 100 AV**——0T=300、1T=400、2T=500 …… 5T=800。每个模式的口径写在 `data/modes.json` 里，可以自己改。
  * ⚡ **配速排轴** —— 行动值换算、N 轮 M 动速度阈值、常见阈值速查表、多角色行动顺序模拟
  * 🎭 **阿哈时刻配速** —— 原版单文件工具**逐字节原样嵌入**（阿哈速度加权、阈值反推、队伍配速、行动值排轴）。原文件在 `features/aha-speed/original.html`，SHA256 有测试守着，谁也改不了；Tailwind 已搬到本地，断网也是原样外观
  * 🎲 **抽卡规划** —— 期望抽数、概率分位、星琼成本、累计概率曲线、参数自检

> 界面支持深链：地址栏里的 `#/honkai-star-rail/speed-plan` 这样的地址可以直接存书签或发给别人。

## 崩铁数据怎么更新

角色、光锥、遗器的数据是抓下来的，游戏更新后重跑一次导入器即可（界面上会显示抓取时间）：

```
python tools/import_hsr_data.py            # 联网抓取（原始响应缓存在 tools/.cache）
python tools/import_hsr_data.py --refresh  # 忽略缓存，全部重抓
python tools/import_hsr_data.py --offline  # 只用缓存，重新生成数据文件
```

产出 `modules/honkai-star-rail/data/` 下的 `characters.json`、`lightcones.json`、`relic_sets.json`、`sources.json`。

数据来源两条腿：

* **米游社官方 wiki 图鉴** —— 角色/光锥/遗器的官方名称、命途、属性、星级、图标、官方页面 id；
* **StarRailRes**（社区维护的游戏数据镜像）—— 基础速度、技能/星魂/行迹文案、光锥叠影文案、遗器套装属性。

> 速度类效果是从文案里**自动抽取的候选**：工具负责把原文摆在你面前，条件是否成立（比如"装备者为同谐角色时"）由你勾选决定。宁可不勾，也别多勾。

## 官方图标 / 立绘是怎么来的

角色头像、立绘、光锥与遗器图标都是**官方图**，但**不打进包里**（全量 60MB+）。做法是：

* 数据文件里只存图片地址（图标带米游社 OSS 的缩略参数 `w_128`，单个约 5KB；立绘约 230KB）；
* 界面要用时走工具箱自己的 `/api/asset?url=…`，服务端**按需下载并缓存**到 `userdata/.asset-cache/`，同一个地址只下一次；
* 之后断网也能显示（读本地缓存）；只允许从米游社/CDN 白名单域名取图。

想清缓存直接删 `userdata/.asset-cache/` 即可。

## 怎么启动

双击 **`start.bat`** → 打开桌面窗口（关掉窗口程序自动退出）。

想要网页版就双击 **`start-web.bat`** → 用默认浏览器打开，服务常驻，`Ctrl+C` 退出。
网页版和桌面窗口版是同一个服务、同一套代码，地址都是 `http://127.0.0.1:8765/`。

命令行也可以：

```
python run.py                 # 桌面窗口
python run.py --web           # 网页
python run.py --no-open       # 只起服务，自己开浏览器
python run.py --port 9000     # 换端口
python run.py list            # 列出所有模块和功能
```

> 没有第三方依赖，**不需要 pip install 任何东西**。只要机器上有 Python 3.10+。
> `start.bat` 会自己找 Python（项目里的 `.venv` → 用户安装的 Python → 系统 Python → DSH 自带运行时）。

## 角色配装与队伍存档

「配速查询」的「我的配装」仍按角色保存一套配置，支持套用、编辑后覆盖和删除。现在也保存首次开大参数，以及可展开填写的模拟补充参数（额外充能、开局资源、出招）。额外充能不含模拟器会自动处理的装备加成；特殊资源角色不使用 ERR。

「阿哈时刻配速」每张角色卡只列当前角色的配装存档，点击「读取」导入；没有存档时按钮禁用。换人使用上方角色选择，不会因读取配装偷偷替换角色。支持的角色以模拟器 roster 为准。角色头像复用 `characters.json` 的本地 `icon`；星神★阿哈等没有本地头像的角色显示文字占位。

角色数据仍来自 `userdata/honkai-star-rail/speed-plan-presets.json`，未迁移或复制到另一套角色库。读取时调用原 `speed-plan/plan` 获取 S0，再校准到模拟器的速度字段，避免行迹乘区和遗器自动加成造成偏差。累计开大拉条不会导入为开局拉条，动态效果继续在完整引擎中触发。专武特效目前只识别模拟器支持的叠1，舞舞舞只识别叠5，其余动态效果会提示核对。

爻光二魂是明确的条件效果：若配速页已勾选结界速度，导入时先扣除它，再由完整引擎按结界状态给全队加速，避免计入两次。完整引擎把行迹放在百分比外，配速页把它放在基础速度内，因此带这类条件变化时不能要求完整模拟的每个时点都等于配速页的静态 S0。

队伍另存于 `userdata/honkai-star-rail/aha-team-presets.json`，包含完整角色参数和全局模拟配置。加载队伍恢复保存时的快照，不自动追随之后改动的角色存档；需要更新时重新读取角色，再覆盖队伍。删除队伍不会删除角色配装。独立网页版则分别复用原 `gt-speed-plan` 存档与 `gt-aha-teams` 队伍存储，保存在当前浏览器中，与桌面 userdata 相互独立。

右侧时间轴直接展示 `simulate.timeline`，不重新排序同 AV 事件；序号是原始事件序号，筛选后可能不连续。轮次使用返回的 `t`，AV 使用返回的 `av`，详细记账点击展开。默认「行动顺序」保留实际动作，「显示全部行动」也展示机制和回能事件。

浏览器验收需独立临时 `GT_USERDATA` 与独立 Edge 配置，避开用户常用服务和已有调试端口：

```powershell
node tools\verify_team_ui.mjs 8961 9437 tools\.cache\team-shots
# 第四个参数可传临时生成的单文件 HTML，额外检查断网存档与模拟。
```

## 应用自动保存

编辑过的输入不再依赖手动另存：配速查询、欢愉队排轴、普通配速排轴、行动值排轴、抽卡规划自动记住输入；角色顶分记住模式、关卡和筛选。页面页签、折叠状态、页面及时间轴的滚动位置也会恢复。回到页面后重新计算结果，不缓存上次计算结果来冒充当前结果。旧版静态工具由外层窗口保存表单，原始 HTML 文件不改动。

桌面端本质是本机服务加独立浏览器窗口，自动状态由 `/api/ui-state` 写入 `userdata/ui-state.json`，因此换浏览器配置后仍能恢复；复制整个 `userdata` 可迁移。浏览器另有按用户目录标识隔离的恢复副本，防止短暂写盘失败丢失编辑。后台写入带时间戳和锁，旧请求不会覆盖较新的输入；保存失败会在页面显示。坏 JSON 先改名留档，不支持的状态格式或版本保留原文件并显示错误。

独立 HTML 没有本机服务，自动状态使用浏览器的 `gt-ui-state-v1`，命名配装和队伍继续使用原有存储。它与桌面 userdata 相互独立；清除浏览器数据会清除 HTML 中的存档，换浏览器或改变文件路径也不保证自动共享。

自动保存的是当前编辑状态，不会自动覆盖你另存的命名配装或队伍；需要固定一套方案时仍使用另存、覆盖和删除。外观、导航和文案设置则直接自动写回已有主题/覆盖文件，恢复默认会一并清除相应编辑草稿，避免下次又恢复旧设置。导航与文案需要刷新才应用到外壳。

持久化浏览器验收（必须用独立测试数据，会测试设置的恢复默认）：

```powershell
node tools\verify_local_state.mjs 8961 9437 dist\配速查询-网页版.html
```

## 为什么这么设计

需求是"后续不断加新功能"，所以核心只有一件事：**目录即插件**。

* 加一个游戏 = 在 `modules/` 下建一个目录，写 `manifest.json`。
* 给游戏加一个工具 = 在它的 `features/` 下建一个目录，写 `feature.json`。
* 后端逻辑放功能目录的 `api.py`，前端界面放 `ui.js`。
* 启动时自动扫描，界面自动出现，**不用注册、不用改核心代码**，点「↻ 重新扫描」连重启都省了。

细节看 **`docs/EXTENDING.md`**（程序里点左下角「📘 扩展指南」也能看）。

## 数据更新

每个模块的数据都在 `modules/<模块>/data/*.json` 里，改文件即可，不用动代码。

* **游戏改版了**：改 `data/gacha_pools.json` 里的概率/保底参数，然后到「抽卡规划」页点一次**参数自检**——它会把模型算出的综合概率和官方公布值对比，偏差超过 2% 就会标黄提醒。
* **你自己的改动不想被覆盖**：写在 `userdata/<模块>/<数据名>.json`，它会盖在模块数据之上。
* 界面上「模块状态」页能看到每个模块当前加载的数据文件和版本。

## 配速查询的独立网页版（单文件）

除了工具箱里的版本，`打包.bat` / `python tools\make_web_standalone.py` 还会生成一个**单文件网页**：

```
dist/配速查询-网页版.html      （约 320 KB，双击就能开，不需要 Python、不需要服务）
```

* **里面有什么**：角色/光锥/遗器数据、效果清单、配速算法、推荐引擎、界面，全部内联在一个 HTML 里；
* **怎么做到的**：`web_api.js` 是把 `api.py` 的算法**逐行移植**成浏览器 JS 的版本（同一套公式、同一个契约 `ctx.call(action, payload)`），界面直接复用 `ui.js`；
* **图片仍然联网取**（官方 CDN），其余功能全离线；「我的配装」在网页版里存 `localStorage`；
* **页面顶部带自检**：打开就用 Python 版算出的 20 条配速 + 2 条推荐逐项对拍，显示"✅ 自检通过 N/N"或列出不一致的地方——算得对不对你自己能看见。

**怎么保证两边不会算得不一样**（这是这种"双实现"最大的风险）：

| 环节 | 做法 |
|---|---|
| 标准答案 | `python tools\make_web_oracle.py` 用 Python 算出基准 → `tests/fixtures/web_oracle.json` |
| 命令行对拍 | `node tools\check_web_port.mjs`（1652 项检查：30 条配速含全部表格单元格与效果清单 + 2 条推荐，容差 1e-6） |
| 页面内对拍 | 同一份基准内嵌进 HTML，打开页面就自动跑一遍 |
| 数据变更 | 数据更新后重跑上面两条命令，对不上会立刻报出来；另有 3 条 Python 测试防止"基准过期导致两边一起错" |

## 可视化后台：外观与排版

侧边栏里的 **🎨 界面 → 外观与排版**（本身就是一个功能模块，走同一套插件机制），用来**可视化修改工具箱自己的样子**，不用碰代码：

| 能改什么 | 具体项 |
|---|---|
| 配色 | 页面背景、卡片背景、次级背景、边框、正文/次要文字、主/次强调色、成功/提醒/警告色（取色器 + 手填色值） |
| 字体与字号 | 界面字体、等宽字体（数字/公式）、基础字号、行高倍数 |
| 布局 | 圆角、侧边栏宽度、内容区留白、卡片内边距 |
| 界面文字 | 工具箱标题、搜索框提示 |
| 一键预设 | 默认深色 / 浅色 / 高对比 / 紧凑 / 大字 |
| 备份 | 保存 / 恢复默认 / 导出主题 JSON / 导入主题 JSON |

* **实时预览**：改任何一项整个界面立刻变；满意了点「保存」才写进 `userdata/interface/theme.json`；
* **只存你改过的项**：没动过的键继续跟着以后的默认值走，不会被旧的固定值锁死；
* **白名单校验**：颜色必须是合法色值、数字夹到合理范围、文字有长度上限——这些值最终会变成页面上的 CSS 变量，不校验等于允许往自己页面里注入任意 CSS（这道闸是特意加的）；
* **单文件网页版也跟随**：打包时把当前主题内联进 `配速查询-网页版.html`，手机上看也是你调好的配色；
* 想改回原样：点「恢复默认」，或删掉 `userdata/interface/theme.json`。

## 手机上也能用

**`手机打开.bat`** 会把单文件网页版挂到局域网，并打印手机能打开的地址：

```
双击 手机打开.bat   →   手机连同一个 Wi-Fi，浏览器打开  http://192.168.x.x:8770
用完在那个黑窗口里按 Ctrl+C 关掉
```

* 只对外提供**那一个已经打包好的 HTML**，没有接口、不暴露源码（工具箱自己的服务仍然只听 `127.0.0.1`）；
* 手机端做了窄屏适配：控件竖排铺满、下拉浮层自动避让屏幕边缘、表格横向滚动、触屏加大点按区域；
* 同一个 Wi-Fi 下别人知道地址也能打开——用完关掉即可。

## 打包：一次出两个包（用户包 / 作者包）

双击 **`打包.bat`**（等价于 `python make_package.py`），产出**两个**包：

| | 用户包（发给别人） | 作者包（你自己用） |
|---|---|---|
| 文件名 | `dist/game-toolbox-v<版本>.zip` | `dist/game-toolbox-v<版本>-admin.zip` |
| `config.json` 里的 `admin` | `false` | `true` |
| 标了 `adminOnly` 的模块（现在是「界面 → 外观与排版」） | **整个模块都不在包里** | 在 |
| `使用说明.txt` | 不提后门 | 会写出来 |
| 单文件网页版内联的外观主题 | 默认外观 | 你自己调的主题 |

两个包都：解压 → 双击 `start.bat` 即用，**不需要 pip install 任何东西**；包里带一份 `配速查询-网页版.html`；
自动排除 `__pycache__`、`userdata/`、`dist/`，以及**所有以 `.` 或 `_` 开头的目录**（缓存、临时目录、比对快照）。

### 后门（作者专用模块）怎么运作

* 模块的 `manifest.json` 里写 `"adminOnly": true`，`core/registry.py` 就只在**后门打开**时加载它；
* 开关：`config.json` 的 `"admin": true/false`（**默认 false**），或用环境变量 `GT_ADMIN=1/0` 临时覆盖；
* **默认关**是有意的：发给别人的包即使漏改配置，也不会把作者工具暴露出去；而用户包里连模块文件都不存在，对方改配置也开不出来；
* 本机安装走作者包：`tools/install_local.ps1` 默认优先装 `game-toolbox-admin-latest.zip`。

命令行等价：`python make_package.py`

## 实现说明（几个刻意的选择）

* **后端只用 Python 标准库**：不装包、不怕断网、升级不会因为依赖打架。
* **桌面窗口用系统 Edge 的 `--app=` 模式**：独立配置目录，不干扰你平时的浏览器；比 Electron 省 200MB 下载，冷启动一秒内。想换成真正的原生壳，只改 `core/launcher.py` 一个文件。
* **前端不打包**：原生 ES 模块 + 动态 `import()`，改完 `ui.js` 刷新页面就是新的（服务端强制 `no-store`）。
* **心跳看门狗**：桌面窗口模式下前端每 2 秒发一次心跳，窗口一关服务自动退出，不会在后台留僵尸进程。
* **静态资源白名单**：`api.py` 之类的源码不会被浏览器拿到（已实测 404 拦截）。



## 角色顶分模块（herta/records）

- 后端 `api.py`：镜像列表 `MIRRORS`，按顺序取 `latest.sha256` + `latest.json`，校验一致才用；缓存 `userdata/herta/records_cache.json`。
- 网页版 `web_api.js`：同一逻辑的 fetch 版（`GT_HERTA_API.createApi({fetch, storage})`，异步）；自检 `node tools/check_herta_web.mjs`。
- 数据仓库 Ca5tor1ce-vesna/herta-data：`python scripts/publish.py <新 json>` 发布。
- 头像/光锥：`avatar_map` / `lightcone_map`（JS 版 `avatarMap` / `lightconeMap`）读崩铁模块的 characters.json、lightcones.json；特例写在 `AVATAR_OVERRIDES`（两边要一致）。
- 单文件网页版里角色顶分的 ui.js 被包进一个函数作用域（避免和配速查询的顶层名字冲突），由 `#herta` 或顶部标签切换挂载。
