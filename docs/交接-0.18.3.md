## 九、纪律（踩过的坑，别再犯）

* **改之前先把要改的那段完整读出来**；锚点用唯一上下文；缩进从目标行复制。
* **改完立刻：语法检查 → 起服务实测 → 跑测试**（三步都要）。
* **别用 PowerShell 的 `Set-Content`/`Get-Content -Raw`+`Set-Content` 改仓库文件**：
  会把行尾翻成 CRLF、可能加 BOM。用 Python **二进制读 → 替换 → 二进制写**。
  （本轮升版本就是这么做的：`core/__init__.py` 是 CRLF、`修改记录.md` 是 LF，都保住了。）
* **`print` 的字符要 GBK 编得出**：`✅ ✓ ✗ ⚠ ❌ 🔄` 一 print 就崩（`① ② ③ →` 是安全的）。
  用 `[OK]/[X]/[刷新]`。**别只在 `make_package.py` 里查 —— 本轮 `build_green.py` 就漏了。**
* **`Join-Path` 遇到以 `.` 开头的路径段**（如 `.asset-cache`）会把下一个参数当 `-Credential`：
  写 `Join-Path $dir ".asset-cache"`。
* **PowerShell 里别用 `< NUL` 重定向**（PS7 不支持），要用 `cmd /c '... < NUL'`。
* **`.bat` 带中文必须保持纯 ASCII 或 UTF-8 带 BOM**（本轮实测仓库里的 .bat 都是 `chcp 65001`）。
* **容器里传中文文件名给外部程序**（gh/git 等）容易被弄坏：先复制成 ASCII 名再传。
  本轮 Release 附件就是先复制到 `F:\gt-push\rel-0.18.3\game-toolbox-v0.18.3-green.zip` 再传的。
* **`gh release view --json` 没有 `isLatest` 字段**（可用的是 `isDraft`/`isPrerelease`），写好脚本前先看报错里给的字段表。
* **别拿 `dist/` 当"上游原样"的参照物** —— 那是用当前树打的包。
* **网页版与 Python 是两份内核**：改 `api.py` 口径必须同步 `web_api.js` 再跑 `check_web_port.mjs`。
* 自查用"**数据 → 文件**"的反向一致性核对（本轮用它确认了三个包里的 `app/index.html` 都是新首页）。
