# 版本更新与打包（照 GitHub 原有口径）

> **权威文档是上游的 `docs/开发说明.md`**（「打包：一次出两个包」那一节）。本文只做三件事：
> 把「升版本要改哪几处」列成清单、记下本机的实际操作、说明哪些助手自加的工具**不属于上游流程**。
>
> 分工：助手只负责**生成内容与产物**；**提交、推 tag、挂 Release 由作者做**。

## 一、升一个版本：只需改 2 处（共 3 行）

| # | 文件 | 改什么 |
|---|---|---|
| 1 | `core/__init__.py` | `__version__ = "x.y.z"` ← **唯一真源**，只改这一行 |
| 2 | `修改记录.md` | 顶部插入一节 `## x.y.z（日期）` + 这次的改动说明 |

**其余全部自动派生，不要手改**（仓库里没有第二处硬编码版本号）：

| 派生处 | 来源 |
|---|---|
| `dist/game-toolbox-v<版本>.zip` / `-admin.zip` / `-latest.zip` | `make_package.py` 读 `__version__` |
| `使用说明.txt` 里的版本 | 同上 |
| `dist/配速查询-网页版.html` 的「工具箱版本」 | `tools/make_web_standalone.py` 正则读 `core/__init__.py` |
| `dist/游戏工具箱-v<版本>-绿色版.zip` | `packaging/build_green.py` 读 `__version__` |
| exe 的版本信息、`/api/health` 的 version | `build_green.py`（spec 的版本资源）+ `core/server.py` |

**改文件时保住行尾**：`core/__init__.py` 在仓库里是 **CRLF**，`修改记录.md` 是 **LF**。
用能识别原行尾的方式改（二进制读 → 替换 → 写回），别让编辑器/PowerShell 把 `\n` 翻成 CRLF
（翻一次就是「3826 行假改动」那种坑）。

## 二、本机打包（上游口径：出用户包 + 作者包）

```powershell
$py = 'C:\Users\Administrator\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe'

& $py make_package.py            # == 双击 打包.bat；出用户包 + 作者包 + 两个 latest
& $py tools\make_web_standalone.py   # 可选：单独出 dist\配速查询-网页版.html
& $py tools\make_source_package.py   # 可选：出源码版 zip
```

产物（`dist/`，**不进仓库**，`.gitignore` 已排除）：

| 产物 | 给谁 |
|---|---|
| `game-toolbox-v<版本>.zip` | 用户包：发给别人（`admin=false`，不含 `modules/interface`） |
| `game-toolbox-v<版本>-admin.zip` | 作者包：自己用（`admin=true`，含后门模块） |
| `game-toolbox-latest.zip` / `-admin-latest.zip` | 固定名副本，`tools/install_local.ps1` 用 |
| `配速查询-网页版.html` | 单文件网页（也会塞进两个包里） |

绿色版**不在本机打**（见下节）。

## 三、绿色版与 Release：走 CI（上游原有流程）

`.github/workflows/build.yml`：推送 `v*` tag（或手动 Run workflow）时，在 windows-latest 上
跑测试 → `python make_package.py --green` → 解压到带中文和空格的路径启动 exe 冒烟
（校验服务响应 + `userdata` 写在 exe 旁边）→ 上传 artifact。

发版顺序：**改完 → 测试全绿 → 改版本号 + 写修改记录 → 提交推送 → 打 `v<版本>` tag → 等 Actions 绿
→ Releases 里下载/分发绿色版 zip**（README 第 1 步指向的就是它）。

⚠️ 本机**没有** PyInstaller，也没装系统 Python（`python` 只是 WindowsApps 存根）——
绿色版交给 CI，不手工打。

## 五、异常处理

* **打包后 `dist\` 里有 `_admin-page.html` / `_user-page.html` 残留**：正常会被清掉；没清掉说明
  打包中途失败，看一眼终端报错。
* **`python make_package.py` 在裸控制台报 `UnicodeEncodeError: 'gbk' codec ...`**：这是上游脚本里
  emoji 的已知问题，只在手敲命令时出现。两个绕法：①走 `打包.bat`；②先
  `$env:PYTHONUTF8='1'`（CI 也是这么设的）。
* **端口**：上游默认 8765。开发/验证用别的端口（例如 8960），别和作者在跑的实例抢。
